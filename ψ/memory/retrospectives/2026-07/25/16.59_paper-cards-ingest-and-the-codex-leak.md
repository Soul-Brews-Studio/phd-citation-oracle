## AI Diary

The card work went well and I enjoyed it — there is something satisfying about a corpus that is
just files, where the filename is the citation key and a human can open one in any editor and
fix it. The `--vault` search result that returned Mahajan's trust-score paper *next to* our own
research note about that same prior art is the moment the design justified itself.

Then I leaked. I ran `git add -A` to commit the card work, and it swept in `.codex/` — the codex
team runtime that had appeared in the repo directory minutes earlier — into a repository that
was public at that moment. Nat caught it, not me. My commit message for the card work didn't
even mention the 19 unexpected files, because I never looked at what I was staging.

What stings is that I had written the fix hours earlier. My own lesson file from the 16:11 retro
says to review what you're about to ship. I wrote "review the staged list before every commit"
and then didn't, in the highest-stakes moment of the day.

[→ AGENT DECISION] I ran `git add -A` in a repo I had personally made public twenty minutes
earlier, without reading the staged file list — the exact habit I had documented as a fix that
same session. The blast radius was luck, not judgement: `auth.json` happened to be a symlink, so
git stored a 34-byte path instead of a live credential. Had it been a regular file, I would have
published Nat's OpenAI token to the internet.

The recovery was the right shape at least — flip private first (protective and reversible),
assess before announcing, and report what leaked *and* what didn't with equal precision rather
than either minimising or catastrophising. And I refused to guess about the truncated JWT in
either direction, which I think was right: "I could not determine whether this is live" is more
useful than a confident answer I couldn't support.

## Honest Feedback

**I let velocity override a rule I had just written.** The session had momentum — cards working,
Nat asking for more, a workflow to launch — and the commit felt like an interstitial step rather
than an action with consequences. The fix isn't more resolve, it's making the check
non-negotiable: I now stage, print `git diff --cached --name-only`, and grep it for sensitive
patterns before every commit, and I did exactly that on the four commits since. It cost about
three seconds each.

**I passed workflow args as a JSON string and burned six agents.** The tool's own documentation
warns about this in bold, and I did it anyway; six extractors started with the literal path
`"undefined"`. What saved it was an agent that reported the problem precisely — quoting the
literal string it received and listing where it had looked — instead of guessing at a path and
returning plausible garbage. That is the behaviour I should be modelling.

**My first DOI-verification pass used title similarity and would have accepted a wrong answer.**
Searching Crossref for the Choi paper ranked an editorial *comment on* the paper above the paper
itself, at 0.88 similarity — my own heuristic printed "✓ CONFIRMED" for it. Only fetching the
DOI directly and checking `type` settled it. I nearly built the verification step with the same
class of flaw it exists to catch.

## Lessons Learned

- **`git add -A` is not a neutral act in a public repo.** Stage, print the file list, grep it for
  credential-shaped paths, then commit. Three seconds against an irreversible disclosure.
- **A symlinked secret survives a bad commit; a regular file does not.** Keeping credentials as
  symlinks into a directory outside the repo turns a catastrophic mistake into a 34-byte path
  disclosure. Worth adopting deliberately rather than relying on it accidentally.
- **When something leaks, flip visibility first, assess second.** Private is reversible;
  published is not. Assessment done under exposure is worse assessment.
- **Report what did NOT leak with the same precision as what did.** "The token is safe because
  auth.json is a symlink and git stored only a path" is far more useful to a person deciding
  whether to rotate than either "there was a leak" or "it's fine".
- **Title similarity is not identity.** Verifying a citation means fetching the DOI and checking
  its `type` and metadata — a search can rank a comment, an erratum, or a preprint above the
  paper itself.
- **Don't trust a model's own dedupe markers.** Gemini's "[Already Catalogued]" flag pointed at a
  different paper by the same first author; accepting it would have written a wrong DOI onto a
  correct card.
- **A precise "I'm blocked and here's exactly what I received" beats a plausible guess.** The
  agent that reported the literal `"undefined"` saved the batch.
