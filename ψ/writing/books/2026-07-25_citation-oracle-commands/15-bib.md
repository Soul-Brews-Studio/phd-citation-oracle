# บทที่ 15: .bib กับบทเรียน 18 ข้อ — ปิดเล่ม

Card 62 ใบ → ไฟล์ `.bib` เดียวที่ `\cite{}` เรียกใช้ได้จริง บทนี้คือคำสั่งสร้าง วิธียืนยันด้วย bibtex ตัวจริง error 18 จุดที่เจอ และที่เราทำพลาดเอง 4 ข้อ

## 15.1 สร้าง `.bib`

```bash
maw citation bib                    # เขียน artifacts/citation.bib
maw citation bib out.bib            # กำหนดปลายทางเอง
maw citation bib --by-topic         # เรียงตาม 6 taproot แทนตัวอักษร
```

อ่านการ์ดใน `ψ/papers/` ดึง frontmatter ประกอบเป็น `@article{}`
เขียนทับทั้งไฟล์ทุกครั้ง — การ์ดคือความจริง `.bib` generate
ซ้ำได้เสมอ

`--by-topic` คั่นกลุ่มด้วย `% ── <topic> ──` เช็คจำนวน paper
ต่อ topic โดยไม่ต้องนับมือ

ไฟล์ขึ้นต้นด้วย header สี่บรรทัดเสมอ — บอกที่มา จำนวน entry
คำเตือนห้ามแก้ไฟล์นี้ตรงๆ:

```
% Citation Oracle ✦ — generated by "citation
% bib" from ψ/papers/
% 62 citable entries of 62 cards · 61 with a DOI
% The cards are the source of truth: edit those,
% not this file.
```

## 15.2 "et al." → `others`

BibTeX ไม่รู้จักคำว่า "et al." — เห็นแล้วเดาว่าทั้งก้อนคือ
นามสกุลเดียว ทางแก้คือใส่ `others` เป็นชื่อคนสุดท้าย แล้ว
style (unsrt, apalike) จะพิมพ์ "et al." ให้เอง

```typescript
function bibAuthors(authors: string[]): string {
  const named: string[] = [];
  let truncated = false;
  for (const a of authors) {
    const cleaned = a
      .replace(/,?\s*\bet\s+al\.?\s*$/i, "")
      .trim();
    if (cleaned !== a.trim()) truncated = true;
    if (cleaned) named.push(bibEscape(cleaned));
  }
  return [...named, ...(truncated ? ["others"] : [])]
    .join(" and ");
}
```

## 15.3 ตัวอย่าง entry จริง — `jarernwong2021`

ไม่มี `doi` ไม่มี `note` (ยังไม่ verify กับ Crossref) แต่ครบ
author/title/journal/year — citable ปกติ

```
@article{jarernwong2021,
  author  = {Jarernwong, K. and Gheewala, S. H. and
             Sampattagul, S.},
  title   = {{Health risk map related to particulate
             matter exposure in Chiang Mai, Thailand}},
  journal = {Chemical Engineering Transactions},
  year    = {2021},
  volume  = {89},
  pages   = {229-234}
}
```

entry ที่ไม่มี `note` = การ์ดที่ยังไม่ verify — ทั้งคลัง 62 ใบ
เจอแค่ใบนี้ใบเดียว

การ์ดที่ขาด field จำเป็นจะไม่หาย แต่ถูกเขียนเป็น comment
ท้ายไฟล์แทน (Rule 1) — ตอนนี้ทั้ง 62 การ์ดครบ ไม่มี withheld

## 15.4 ยืนยันด้วย bibtex จริง

```bash
pdflatex citecheck.tex   # รอบ 1: สร้าง .aux
bibtex   citecheck       # อ่าน .aux + citation.bib → .bbl
pdflatex citecheck.tex   # รอบ 2: ดึง .bbl มาประกอบ
grep -c '\\bibitem' citecheck.bbl   # นับ = 62
grep -i warning citecheck.blg       # ว่างเปล่า = 0
```

`\nocite{*}` ดึงทุก entry มาโดยไม่ต้อง cite ทีละตัว — 62 entry
ตรงกับ `citation.bib`, 62 `\bibitem` ใน `.bbl`, **0 warning**
หนักแน่นกว่าเชื่อ exit code ของสคริปต์ตัวเอง

## 15.5 error 18 จุด — แยกประเภท

diff การ์ดกับสถานะก่อน verify (`051014b`) แยกเฉพาะ error จริง
ไม่นับ reformat/benign — เต็มที่ `artifacts/citation-audit.md`

| ประเภท error | จำนวน | citekey ตัวอย่าง |
|---|---|---|
| ผู้เขียนคนแรกผิดคน | 7 | buya2025 (เดิม taneepanichskuld2025) |
| title แต่งขึ้นเอง | 1 | she2019 |
| เลขหน้าผิด | 7 | yu2023, ravindra2024, chen2024 |
| journal ผิด | 1 | thongsame2024 |
| volume ผิด | 2 | buya2025, chen2024 |

รวม 18 จุด ใน 14 การ์ด — `chen2024` โดน 3 จุดพร้อมกัน (author,
pages, volume) นอกกลุ่มนี้มี 8 จุด benign completion กับ 2 จุด
reformat — ไม่นับเป็น error

เคสหนักสุด: `buya2023` กับ `wongnakae2023` — citekey เดิมมาจาก
"Amnuaylojaroen, T." ที่ไม่อยู่ใน author list จริงของบทความ
ไหนเลย เอา author ของ paper อื่นมาแปะผิดใบ

ทุกการ์ดที่ rekey เก็บ citekey เดิมไว้ที่ `aka:` — `buya2025`
มี `aka: taneepanichskuld2025` ไม่มีใบไหนถูกลบทิ้งจริง

**คำเตือน**: rekey แล้ว vector store เก่ายังผูก embedding กับ
citekey เก่า — `citation doi --write` เตือนทุกครั้งที่ rekey
เกิดขึ้น:

```
Re-index so the store matches the new keys:
citation index --vault
```

ไม่งั้น `search` กับ `graph` จะยังพูดถึง citekey ที่ไม่มีการ์ด
รองรับแล้ว

## 15.6 เลขหน้าจาก DOI — บั๊กเงียบที่สุด

4 ใน 7 จุดเลขหน้าผิด มาจากหยิบเลขท้าย DOI มาเขียนเป็นเลขหน้า
ตรงๆ — journal born-digital (npj, Scientific Reports) ใช้
"article number" แทนเลขหน้า เลขฝังอยู่ใน DOI เอง หยิบผิดตัว
ได้ง่าย

| citekey | DOI ลงท้าย | เขียนไว้ | จริง |
|---|---|---|---|
| yu2023 | -00363-w | 363 | 41 |
| ravindra2024 | -00833-9 | 833 | 326 |
| villarrealmarines2024 | -00837-5 | 837 | 293 |
| koziel2025 | -02069-w | 2069 | 18573 |

บั๊กนี้เงียบเพราะดูสมเหตุสมผลทุกกรณี — ต่างจาก title ที่แต่ง
ขึ้นซึ่งเทียบ DOI แล้วได้ similarity ต่ำจนจับได้ (0.33) เลขหน้า
ไม่มี signal บอกว่าผิดเลย ต้องดึง field เต็มจาก Crossref มา
เทียบทีละตัว ไม่ใช่แค่เช็คว่า DOI resolve ได้

error กลุ่มนี้ไม่เคยโผล่ตอน `search`/`graph` เพราะสิ่งที่ถูก
embed คือ `title + summary + thesis_relevance` เท่านั้น เลขหน้า
ไม่เคยอยู่ในเวกเตอร์เลย `citation doi --all` กับ bibtex จึงต้อง
คู่กับ `search` ต่อไป

## 15.7 ที่เราผิดเอง

| ผิดอะไร | บทเรียน |

| นับ error ตัวเองผิด (`c01b2f5` บอก 11, จริง 18) | สร้าง `citation-audit.md` generate จาก git diff จริงแทนคำกล่าวอ้าง — ไม่ rewrite commit เดิม |
